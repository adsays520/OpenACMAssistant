# OpenACM-Assistant 新版参赛视频拍摄流程

日期：2026-10-30。按约6分钟成片设计，主线为“提出目标 → 自由探索 → 工具验证 → 经验复用”。

本文中的拍摄问句已先交给本机 `deepseek-script` 实际验证：11/11轮问答与计划检查通过，另有3/3轮真实短流程通过。短流程实际完成4位精确乘法器的256组输入穷举，错误数为0。问句、最终回复、完整计划与检查结果见[拍摄问句验证报告](拍摄问句验证报告.md)。

本版重点展示自由探索的交互和真实决策记录，再用两级优化、持久经验与完整后端说明工程深度。长实验使用带任务编号的历史结果；现场短仿真使用本次录制产生的新结果。所有镜头均有对应素材，见[演示素材索引](演示素材索引.md)。

## 二、录制前准备

1. 录制1080p横屏，终端字体约20–24px，宽度至少100列。终端与IDE分段全屏展示，数字和曲线保留约3秒静止画面。
2. 先退出仍在运行的旧版聊天窗口，再启动当前代码。段落内连续交流；切换独立实验段时使用 `/new` 清除草案。录制中的新任务要使用它自己产生的结果。
3. 预先打开：完善版技术报告、自由探索曲线、ACCO阶段报告、后端布线图、源完整性文件。文件位置见素材索引。
4. 拍摄两遍：先完整录屏保留真实过程，再补录数字、曲线和文件目录特写。等待模型或EDA的长片段可剪辑压缩，字幕注明“等待已压缩”。

在Bash中执行：

```bash
cd /data2/huangjj/OpenACMAssistant
export OPENACM_SOURCE=/data2/huangjj/OpenACM
export OPENACM_OLLAMA_URL=http://127.0.0.1:11435
export OPENACM_MODEL=deepseek-script
/data2/huangjj/DeepSeekLocal/deepseek.sh status
./openacm-assistant.sh doctor
./openacm-assistant.sh chat --theme ocean
```

模型服务未启动时，先在Bash执行 `/data2/huangjj/DeepSeekLocal/deepseek.sh start`。`doctor`用于检查工具与隔离环境；拍摄问句是否可用，以实际对话验证为依据。

## 三、逐段输入与拍摄重点

以下为聊天窗口输入，逐条输入、等待回答，不要一次粘贴整段。`/new`、`/plan`、`/exit`是聊天命令；上节的启动命令在Bash执行。

### 片段A：能交流，也能完成短实验

```text
/new
你能干什么？
/plan 做4位精确乘法器，穷举所有输入。
开始运行
刚才的仿真结果如何？验证了多少组输入，错误数是多少？
```

依次拍到可读计划、真实进度、最终总结。应看到256组输入、0错误及功能验证结论。4位穷举是现场短流程，不能拿它的输入数说明8位设计已穷举。

可补录的参数交流，已单独验证：

```text
8位乘法器有哪些参数？MRED是什么意思？
```

这条补录安排在独立片段中，不插入短仿真的“开始运行”与结果追问之间。

### 片段B：自由探索——本片核心镜头

```text
/new
探索8位近似乘法器，采用LLM，预算8个候选，限时10分钟，固定种子42、采样4096组，要求MRED≤0.02，优先减小综合面积。先给我看计划，不执行。
这个计划是否已经达标？
```

此处只预览。回答应明确尚未仿真；计划应包含8位、4096组、种子42、MRED约束、600秒总预算和两级编排。8项是架构评价上限，另有入选实测与每个父项的器件预算，不能把它说成整个流程只调用8次工具。

然后开始一个独立的历史结果展示段，在画面持续保留字幕“历史真实探索回放｜任务20261011_140055_explore_multiplier_fdabd4”：

```text
/new
总结任务20261011_140055_explore_multiplier_fdabd4的探索结果：执行了多少个候选，最佳达标项的MRED和综合面积是多少？
之前这些探索数值可以做什么？先不要启动新实验。
```

穿插如下镜头，构成一个完整证据链：

1. 自由探索流程图：目标/约束→合法菜单→模型选择→工具评价→反馈→下一候选。
2. 该任务第6轮的 `menu.json` 与 `selection.json`，只解释候选配置、所选编号与来源。
3. `candidates/0006/result.json` 的实测指标与约束判定；模型的选型理由不能当作已达标的证明。
4. 面积收敛曲线和误差—面积散点图，指出最佳面积在第6条记录后未继续改善。
5. 终端直接给出历史任务结果与后续用途，观众无需自行寻找报告。

128条记录来自旧单级实测探索；上一镜头的8候选计划属于当前两级ACCO。两者分开标注任务与流程，避免把历史结果接成这次预览产生的结果。9.64%是同任务综合面积的变化，不能说成功耗、时延或整PE的同等改善。

若确实要补录一项新的长探索，可在Bash运行本次已验证的完整计划：

```bash
./openacm-assistant.sh acco --spec docs/video-demo/2026-10-30/evidence/validated_free_plan.json
```

该命令会启动真实EDA，主片默认无需执行。录制时保留新任务编号和最终状态；600秒耗尽应展示未完成状态，不能补接旧任务的结果。验证本拍摄问句时没有运行这项8候选长实验。

### 片段C：两级优化与容量规格

```text
/new
探索SRAM，总容量4KB，输出字宽8位，架构用LLM，器件用随机，预算4个候选，限时10分钟。先给我看计划，不执行。
这里的bank是什么意思？
```

重点放大总容量32768bit和输出字宽8bit。接着展示真实ACCO乘法器阶段表，说明预测、RTL/综合/STA复核、器件SPICE分别留痕。

需要器件/PVT画面时，使用素材索引中的64bit SRAM结果，字幕标注“64bit独立器件链路验证”。该实验为3种PD尺寸×3个PVT组合、每组合MC=2；单阵列读写/SNM来自SPICE，bank外围与面积为估算。这里展示器件复验能力，不作为4KB已完成优化或宏级良率的证据。

### 片段D：持久经验与跨模型接入

```text

/exit
```

再在Bash中执行：


### 片段E：完整后端与工程可信性

主片直接展示已有16×8参考DCiM报告、阶段表和DEF布线视图，字幕标明“历史参考后端验证”。

如需补录自然语言计划镜头，重启chat后逐条输入；该问句已验证，但录制主片不要求重跑后端：

```text
/new
/plan 做16×8精确DCiM全流程，穷举乘法输入，时钟周期10ns，要求setup slack不低于0ns、hold slack不低于0ns、布线DRC不超过0。
```

对应历史证据为：65536组乘法输入、错误数0；setup slack=4.64506388ns；hold slack=0.03318188ns；布线DRC=0；综合后、布线后及SDF后各306次有效输出检查。65536组是乘法输入穷举，PE后端功能检查有自己的306次覆盖范围。

最后打开片段A新任务的目录，展示 `inputs/`、`workspace/`、`artifacts/`、`logs/`、`reports/` 和 `source_integrity.json` 中的 `unchanged=true`。观众能同时看到生成文件归档和原内核保护。

## 四、可直接照读的开场与结尾

开场：

> 电路设计往往要反复修改配置、启动仿真、比较指标。我们的作品把这条流程交给本地智能助手：用户用自然语言说明目标、边界与预算，系统组织自由探索，让电路工具给出真正的评价结果。

结尾：

> 本作品的亮点，是连续对话驱动的自由探索、架构与器件的两级编排，以及能够长期复用的设计经验。底层电路能力来自OpenACM，上层助手负责把需求、工具、结果和经验连接起来。每个结论都能回到对应的配置、日志和验证记录。

主片保留短仿真和自由探索的完整叙事。若限定3分钟，可分配为：开场15秒、短仿真35秒、自由探索70秒、两级编排与经验30秒、后端和可追溯性30秒。参数问答、bank定义及新的长探索录制可作为补充视频。

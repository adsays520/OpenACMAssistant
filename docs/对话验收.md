# 对话示例验收

验收对象是用户最终看到的回复和实际生成的计划。仅判断关键词路由、模型返回了合法JSON，或在预设上下文中成功，不足以证明文档示例可用。

`verification/fixtures/dialogue_examples.json`保存示例来源、完整输入、多轮顺序、期望动作、必须落实的字段与回答要点。覆盖README常用问答、E1参数继承与澄清、E2搜索对照及条件先行、E3未接通边界、E5固定组织复验，以及咨询和明确禁止执行。条件先行用例在两轮之间从磁盘恢复会话；E5用例先放入乘法器对照上下文，再输入用户的SRAM复验原话。E2另包含三方法完整任务书，以及保留旧“只比较架构选点”失败需求后再次提交的场景，不能只验证没有方法声明的简短示例。

连接本机Ollama后运行：

```bash
.venv/bin/python -B verification/verify_examples_live.py
```

也可以只复查一个完整场景，例如：

```bash
.venv/bin/python -B verification/verify_examples_live.py --cases sram_followup e5_fixed_retest
```

模型与地址沿用`OPENACM_MODEL`和`OPENACM_OLLAMA_URL`。脚本真实调用对话模型和单点规划器；搜索对照与固定组织复验由对应受约束解析器形成计划。它禁止调用所有EDA执行入口，需要时明确使用计划预览。通过表示对话和计划符合这些标注，不能写成电路仿真通过、任意问法都能理解或E3消融已实现。

每次验证放在独立`runs/*_example_acceptance_*/`，包括固定的cases、逐轮请求/最终回复/字段检查、report、result和OpenACM原文件完整性校验。模型服务错误、无效输出和规则回退均不能计作真实模型通过；失败记录保留。该集合用于开发回归，已经据此修复代码，不能当作独立留出测试集宣称泛化准确率。

无需模型的回复契约回归：

```bash
.venv/bin/python -B verification/check_response_contract.py
.venv/bin/python -B verification/check_chat_output.py
```

前者检查复合问题、自然计划、重启后的回复一致性及运行/异常审计；后者调用实际chat循环检查终端呈现。mock执行器仅用于检查调用和失败处理，不代表实际EDA成功。

每轮对话目录中，`answer.md`保存工具处理后的最终回复，`final_plan.json`保存相应完整计划；`dialogue_answer.md`只保存对话模型选出的初步文本。`metadata.json`分开记录模型动作、最终动作、是否进入执行和关联任务。旧审计不回写，早期空白answer不能视为当前版本的最终回复。

新示例或用户反馈应加入这个集合，同时检查初次输入、条件补充、咨询插入、重启和电路切换。修改后重跑受影响场景，并在整体验收通过后更新验证记录。尚未接通的功能直接说明具体缺口、保留条件，不输出无关能力介绍或替换实验。

运行中的Python聊天进程保留启动时加载的代码。更新代码后应退出旧chat，再执行`./openacm-assistant.sh chat`；已有会话会从本地恢复。`ask`是一轮独立请求，需要多轮继承时使用chat。

2026-10-30新增的参赛视频问句使用`video_20261030_*`场景，覆盖自由探索预览、指定历史任务分析、连续数值用途追问与经验库。完整验证和拍摄材料见[视频问句验证报告](video-demo/2026-10-30/拍摄问句验证报告.md)。另有`verification/verify_video_short_flow.py`真实运行4位精确乘法器，验证“预览→开始运行→结果追问”，会启动EDA；与禁止EDA的`verify_examples_live.py`范围分别记录。

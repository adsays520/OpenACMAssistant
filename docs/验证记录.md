- 原 `sram_6t_cell.yaml` 配置对应PU/PD/PG120/180/70nm、L74nm，在本次16×8、TT、1V条件下write测量TWRITE_Q/TWRITE_QB=FAILED。结果保留在 [失败报告](../runs/20261008_215746_sram_ad0d07/reports/report.md)。参考配置90/90/135nm、L50nm的完整读写/SNM流程通过。

## 重复数组导致截断的修复

用户请求“做8位近似乘法器，所有近似位置用sabetz，固定种子采样4096组，要求MRED≤0.02”时，旧规划器两次生成无限重复的compressor_ids数组，在1600 token上限截断，done_reason=length；JSON解析位于重试保护之外，显示Expecting value。原始失败回复保留于 `runs/20261008_234746_planning_ffa91e/` 与 `runs/20261008_235048_planning_eb7a13/`，没有进入仿真。

修复后，同种压缩器的规划schema移除compressor_ids，仅用compressor_id。逐位置列表按位宽限制为floor((n−2)²/4)项，已与原生成器4–32位逐一核对；operations最多5项、constraints最多16项。截断和无效JSON均进入一次受控重试，不把错误数组重新喂给模型；连续失败会明确说明尚未仿真。采样数量、显式种子及exhaustive=false落实为必需值，避免继承旧穷举计划。

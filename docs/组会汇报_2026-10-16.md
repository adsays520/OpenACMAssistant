# OpenACMAssistant 项目进展与操作演示

汇报日期：2026 年 10 月 16 日（北京时间）  
建议时长：15–20 分钟；正文用于汇报，附录用于演示和复现。  
证据范围：2026-10-08 至 2026-10-11 的本机运行记录；本次整理另行核对 CLI、依赖路径、经验库统计和公开数据状态。文中历史结果没有在本次文档整理中重新仿真。

## 1. 项目定位与当前结论（1 分钟）

OpenACMAssistant 是本地 DeepSeek 驱动的 OpenACM 电路仿真与设计空间探索助手。用户用中文提出设计需求，系统整理结构化参数，在独立工作副本中调用 EDA 工具，再根据实际测量判断约束并输出中文报告。

当前已经实现从“需求理解”到“真实工具执行、结果验收、反馈探索、经验积累”的闭环。原始 OpenACM 提供电路生成器、网表、模型和参考库；本项目重点实现外部交互、参数适配、可靠执行、证据管理及探索调度。

可直接用于开场的表述：

> 目前项目已经可以通过中文完成 SRAM、乘法器、压缩器和 DCiM 的设计评估，并用实际仿真结果判断是否达到要求。进一步可以在给定预算内探索候选，把测量结果反馈给模型，并持久保存经验供后续检索。接下来需要重点评价模型选择策略是否比相同预算的基线更有效。

## 2. 为什么做这个项目（1 分钟）

电路评估涉及 Python 生成器、YAML 配置、RTL、SPICE 网表、工艺库和多个 EDA 工具。一次“改变参数后再比较”的工作，需要同时处理设计参数、运行条件、验收指标和文件组织，手动串接容易遗漏条件。

本项目围绕三件事组织流程：

1. 把自然语言落实为可检查的设计配置。例如，“MRED≤0.02”进入验收约束，“用 sabetz”进入压缩器字段。
2. 建立真实执行和结果追溯链路。每个数字能够回到任务、配置、日志和原始测量。
3. 让迭代复用历史信息。连续修改继承已有条件，探索读取已测反馈，新任务可检索历史经验与公开配置参考。

## 3. 系统架构与一次请求的处理过程（2 分钟）

```text
中文问题 / 连续对话
        ↓
咨询、澄清、计划草案、执行或探索
        ↓
本地 DeepSeek + 能力事实 + 设计上下文
        ↑                    ↑
本地已测经验            公开配置参考
        ↓
结构化 JSON → 类型、单位、参数范围、约束与预算校验
        ↓
独立任务目录 + OpenACM 普通文件副本 + Landlock 写保护
        ↓
Xyce / Icarus / Yosys / OpenROAD / OpenSTA / VCS
        ↓
实际指标 → 约束验收 → 中文总结与审计文件
        ↓
记录经验；探索时反馈历史并选择下一候选
```

模型负责理解问题、提出配置、从合法候选菜单中选择下一步，以及组织结果说明。执行器负责参数检查、调用工具、读取数字、判断约束及候选排名。模型输出不能直接成为执行脚本或测量结果。

例如“做 8 位近似乘法器，固定种子 42，采样 4096 组，要求 MRED≤0.02”，需要分别落实：

| 类别 | 对应内容 |
|---|---|
| 设计规格 | workflow=multiplier，bit_width=8，kind=approx |
| 可调配置 | compressor_id 或逐位置 compressor_ids |
| 评价条件 | samples=4096，seed=42，exhaustive=false |
| 验收约束 | mred ≤ 0.02 |
| 优化目标 | 若需要探索，再明确最小化面积等目标 |
| 预算 | 候选数与最长运行时间 |

咨询不会仅因为出现“仿真”或“探索”等词就自动启动 EDA。`/plan` 保存草案，之后“开始运行”才执行；结果追问读取实际任务，草案不当作已测结果。

主要实现对应：`app/assistant.py`（CLI 与编排）、`conversation.py`（对话）、`spec.py`（参数校验）、`worker.py` / `bindings.py`（执行与适配）、`guard.py`（隔离）、`exploration.py`（探索）、`experience.py`（经验）、`public_dataset.py`（公开数据）、`result_summary.py`（总结）。

## 4. 当前支持范围（2 分钟）

| 工作流 | 可提出的主要要求 | 实际评估方式与输出 |
|---|---|---|
| SRAM | 行列、电压、温度、工艺角、PU/PD/PG 尺寸、外围倍率、RC、读写/SNM、Monte Carlo | Xyce SPICE；读写延迟、平均功耗、三种 SNM、单元估算面积 |
| 整数乘法器 | 4–64 位，exact/approx/log，压缩器分配，采样或小位宽穷举 | Icarus RTL；误差率、MAE、MRED、NMED；synthesis 模式增加综合映射面积与门级对照 |
| 压缩器 | 八种模板，电压、温度、NMOS/PMOS/沟道长/负载倍率 | Xyce；传播延迟、平均功耗、门面积及粗略面积估计 |
| DCiM | 行数、位宽、乘法器、存储实现、时钟和后端级别 | functional / synthesis / asic；完整后端包含布局布线、寄生、STA、SDF 和活动功耗 |
| 浮点乘法器 | Exact、AC、EAFPU、MMBS、SSFPM 等 14 个变体及各自合法参数 | 独立 RNE 浮点参考对照、特殊值边界检查、可选综合面积 |

需要在介绍时说明的边界：

- SRAM 是单阵列接口，单点最多 65,536 bit；行数要求为 2 的幂。输入范围不等于每个配置都能正常读写。
- 整数穷举只开放 4–8 位；Log 只开放 8/16/32 位。部分原生尺寸通过外部 8 位分块适配器实现，实际架构留档。
- DCiM 的 16×8、32×16、64×32 有匹配参考宏；其它尺寸可采用标准单元存储，不能称为新增 6T SRAM 宏。
- SRAM 的 W/L SPICE 调整没有自动重新表征后端宏库；两者不能作为同一修改后宏的完整验证。
- 已发现部分浮点模板的特殊值边界错误，因此“生成和仿真完成”不能表述为 IEEE 全面正确。

## 5. 代表性实测结果（3 分钟）

### 5.1 功能、SPICE 与近似设计

| 任务与条件 | 历史实测结果 | 支持的结论 |
|---|---|---|
| 8 位精确整数乘法器，穷举 | 65,536 对输入，0 错误 | 该 RTL 在全部 8 位无符号输入上通过功能对照 |
| 16×8 SRAM，1 V、TT、27℃，PU/PD/PG=90/90/135 nm，L=50 nm | 读/写延迟 0.360010 / 0.318309 ns；平均读/写功耗 38.98886 / 29.64637 µW | 该配置完成读写 SPICE；延迟采用内置测量定义 |
| 同一 SRAM 的 SNM | hold/read/write = 0.358806 / 0.237100 / 0.889950 V | 目标 bitcell 的内置 SNM 测量完成，不能据此推出整阵列良率 |
| sabetz，NMOS/PMOS 加宽 10%，1.2 V、27℃ | 延迟 0.891915 ns；平均功耗 0.256517 µW | 模板尺寸调整实际进入 Xyce；模型为简化 LEVEL=1 |
| 8 位近似乘法器，全部 sabetz，4096 组 | MRED=0.4928234137，大于 0.02 | 仿真完成但未达标，系统保留 infeasible 结果 |
| 8 位近似乘法器，compressor_id=7，综合及穷举复测 | MRED=0.0142197195；综合映射面积 291.802 µm²；43,073 对输入存在误差 | 满足 MRED≤0.02，属于允许误差的近似设计 |

MRED 表示平均相对误差，当前实现排除精确参考乘积为零的输入；0.02 对应 2% 的平均相对误差上限，不能解释为“错误率低于 2%”。上述近似设计可有较高错误率，同时满足平均误差约束。

证据：[精确乘法器](../runs/20261008_220812_multiplier_34456e/reports/report.md)、[SRAM](../runs/20261008_221059_sram_35883b/result.json)、[压缩器](../runs/20261008_215614_compressor_4daaeb/reports/report.md)、[全部 sabetz 未达标](../runs/20261008_235831_multiplier_eb20a5/result.json)、[近似乘法器穷举复测](../runs/20261010_144052_multiplier_e7ddb8/result.json)。

## 6. 设计空间探索：如何从单次评估走向迭代（2 分钟）

探索采用“合法候选菜单 → DeepSeek 选择 → 实际执行 → 约束验收 → 更新历史、最佳项和 Pareto 集合”的循环。每次固定尺寸、测试集合、随机种子、后端和相应模型条件，避免通过改变评价口径获得表面改善。

默认每类预算为 64 个候选、7200 秒；候选数和时间共同生效。`--workflow all --budget 64` 表示每类最多 64 个，不是整个工程合计 64 个。

| 已有探索 | 有限候选内的结果 |
|---|---|
| SRAM，64 候选 | 最佳已测读功耗 26.51181 µW，读延迟 0.4236304 ns；配置含 0.9 V、PU60 nm、外围及列复用调整 |
| 8 位整数乘法器，64 候选 | compressor_id=7，4096 组 seed=42，MRED=0.0136390362，综合面积 291.802 µm²；随后进行穷举复测 |
| 修复后 DCiM，候选预算 64、时间预算 1800 秒 | 实际执行 32 个：6 个达标、19 个未达标、7 个失败；时间用尽停止。最佳候选面积 7610.9788 µm²，MRED=0.0136390362 |
| 浮点，27 个不同候选 | 没有候选同时满足 MRED≤0.02 与 special_mismatch_count=0 |

DCiM 这一轮测量的是含宏的综合映射面积，不能写成路由面积；旧 DCiM 探索的宏接入问题已由独立重跑结果替代。

当前能证明探索闭环可运行并找到有限候选中的达标项。尚未通过相同预算、多随机种子和统一搜索域的系统对照，证明 DeepSeek 优于随机或确定性策略；本阶段不报告模型带来的提速比例或全局最优结论。

证据：[首次探索汇总](../runs/20261009_015053_exploration_suite_ef5061/report.md)、[修复后 DCiM 探索](../runs/20261010_143300_explore_dcim_e42ef3/report.md)。

## 7. 持久经验与公开数据：目前怎样帮助模型（2 分钟）

### 7.1 本地经验库

任务完成后，把参数、指标、约束、失败原因、执行环境和证据路径记录到 `experience/experience.sqlite3`，并提供标准 JSONL 交换文件。新规划和探索按电路、尺寸和评价条件检索历史，符合当前搜索域的历史配置仍需要重新仿真。

本次读取的统计快照为：761 条当前观测、856 个保留修订，67 条当前观测带执行环境记录。当前状态分布为 completed 344、infeasible 185、failed 229、unverified_constraints 3。

这 761 条不能当作 761 个独立、同条件、可直接训练的有效样本。旧任务缺环境信息、重复测量和失败记录都需要筛选；环境信息完整也仍需检查实际评价范围和数据质量。

### 7.2 公开数据接入与本地复测

已下载并核验公开 8 位乘法器数据固定快照，包含 50,000 个唯一配置，每配置有 9 个压缩器选择。数据独立放在 `datasets/`；本地按唯一配置划分 46,000/2,000/2,000，仅训练划分进入检索与候选生成。

用八类压缩器的真值表核对了公开编号 0–7 与助手编号 1–8 的对应关系，并让本地 DeepSeek 实际读取参考、选择候选后复测。

| 40499 | 0.01927266 | 0.0216472906 | 不通过 |

## 8. 可靠性与当前验证范围（1 分钟）

原始 OpenACM 只读；生成和仿真在独立普通文件副本中运行。Landlock 限制执行进程及子进程在任务目录之外写入，隔离不可用时拒绝执行。任务前后保存 SHA-256、大小、权限及修改时间校验。

已有真实尺寸矩阵包含 140 个任务：138 个完成、2 个失败。整数精确/近似 4–64 位逐整数位宽使用每点 64 组边界与随机输入检查；大位宽结果是采样证据。SRAM 64×32 在追加正常预算后完成读写；浮点边界错误保持可见。

已有回归覆盖输入与隔离、截断 JSON 恢复、结果总结、防虚构事实、探索约束与续跑、经验库、公开数据和对话链。发布回归记录中的四项检查均通过；后续经验与对话等检查的既有执行记录见验证文档。本次只整理文档并核对入口，没有重新运行整套回归或完整 EDA。

状态解读：`completed` 要结合实际已测指标及约束阅读；`infeasible` 表示仿真完成但未达标；`unverified_constraints` 表示要求指标未测得；`failed` 表示执行或测量失败。探索的 `completed` 还可能表示预算内正常结束，需另看是否存在可行候选及停止原因。

## 9. 下一阶段计划与可讨论问题（1 分钟）

| 优先级 | 建议工作 | 可验收产物 |
|---|---|---|
| P0 | 先固定 8 位近似乘法器问题，补齐统一环境、评价条件与有效配置数据 | 去重配置集、训练/验证/测试划分、明确的面积/误差标签 |
| P0 | 同搜索域、预算和测试集合对照 DeepSeek、确定性与随机选择，多种子重复 | 最佳可行面积随评估次数曲线、首次找到可行项的成本、失败率、模型调用开销 |
| P1 | 先对已有可靠标签训练面积/误差代理模型，再考虑预测筛选 | 留出集预测误差、排序质量、约束判断及真实复测结果 |
| P1 | 在有限配置上补齐延迟和功耗口径 | 同库、同负载、同活动条件下的真实标签 |
| P2 | 修复或限定浮点边界问题，逐步扩展更多电路与后端场景 | 专用边界回归与可复现后端任务 |

建议组会讨论：先把研究问题聚焦为“在固定真实仿真预算下，更快找到满足误差约束的低面积设计”，再评价经验检索、公开参考和模型选择各自贡献。

## 10. 现场演示流程（约 4 分钟，可替换部分正文）

### 10.1 会前准备

在本机终端执行。以下使用当前机器的实际目录；其它机器需要替换路径并安装依赖。

```bash
cd /data2/huangjj/OpenACMAssistant
export OPENACM_SOURCE=/data2/huangjj/OpenACM
export OPENACM_OLLAMA_URL=http://127.0.0.1:11435
export OPENACM_MODEL=deepseek-script
./openacm-assistant.sh doctor
```

本次 `doctor` 查到 Landlock ABI=4，Xyce、iverilog、vvp、yosys、openroad、sta、vcs、gcc 路径均存在。`opensta` 为 None，但 `sta` 可用。该命令只核对路径与 Landlock，不验证模型推理、VCS 许可证或完整工具运行状态。

如本地模型服务未启动，再执行：

```bash
/data2/huangjj/DeepSeekLocal/deepseek.sh start
/data2/huangjj/DeepSeekLocal/deepseek.sh status
```

会前试跑一次下面的短流程，并预先打开 10.3 中的回放材料。模型响应和 EDA 运行时间取决于现场资源，4 分钟只是演示安排，不是性能承诺。

### 10.2 主演示：咨询 → 计划 → 运行 → 追问

启动聊天：

```bash
./openacm-assistant.sh chat --theme ocean
```

随后在聊天提示符中逐行输入；这些是聊天内容，不是 Bash 命令：

```text
你能干什么？
MRED是什么意思？
/plan 做4位精确乘法器，穷举所有输入
开始运行
刚才结果是否达标，验证了多少组输入？
/exit
```

观察三个点：咨询阶段不启动仿真；`/plan` 只显示并保存草案；明确执行后报告 4 位输入穷举共 256 对，正确性以新任务实测为准。已有同类真实问题链测得 256 对、0 错误。

有时间时，可在退出前增加下面两句，演示连续修改及约束继承：

```text
其余不变，只把位宽改为8位，重新穷举验证
解释刚才结果，指出采样和穷举的区别
```

## 附录 A：可直接使用的命令与操作

### A1. 单点仿真与配置执行

下列 `ask` 命令各自独立，不共享上一次 `ask` 的聊天上下文；需要“其余不变”时使用同一个 `chat` 会话。

```bash
# 只生成计划，不执行 EDA
./openacm-assistant.sh ask '做8位精确乘法器，穷举所有输入' --plan-only

# 自然语言直接执行
./openacm-assistant.sh ask '做8位精确乘法器，穷举所有输入'

# 展示未达标情形：保持用户指定的 sabetz，不自动换电路
./openacm-assistant.sh ask '做8位近似乘法器，所有近似位置用sabetz，种子42采样4096组，要求MRED≤0.02'

# SRAM 读写及目标 bitcell 三种 SNM
./openacm-assistant.sh ask '做16行8列SRAM，1V、27℃、TT，PU90nm、PD90nm、PG135nm、L50nm，跑读写和三种SNM'

# 压缩器尺寸变化
./openacm-assistant.sh ask '把sabetz的NMOS和PMOS都加宽10%，1.2V、27℃，运行Xyce仿真'

# 用已保存 JSON 复现，跳过模型总结
./openacm-assistant.sh run examples/multiplier.json --no-model-summary
./openacm-assistant.sh run examples/sram.json --no-model-summary
./openacm-assistant.sh run examples/sram-sweep.json --no-model-summary
```

预览任务会输出规划目录。若要执行该份确切计划，复制实际路径后运行 `run <规划目录>/plan.json`；不要把包含尖括号的占位符直接粘贴到 Bash。

### A2. DCiM 功能与完整后端

```bash
# 基础功能任务
./openacm-assistant.sh run examples/dcim.json --no-model-summary

# 完整 ASIC 后端：16×8、10ns、setup/hold≥0、DRC=0
./openacm-assistant.sh run examples/dcim-full.json --no-model-summary

# 四类参考任务统一验证，含 DCiM 完整后端
./openacm-assistant.sh full-flow

# 固定参考配置，跳过模型规划及模型总结
./openacm-assistant.sh full-flow --without-model
```

`full-flow` 是 SRAM、整数乘法器、压缩器、DCiM 四类参考链路，不代表五类所有参数组合的覆盖。完整后端单任务总预算 1800 秒、各 EDA 阶段 600 秒；功能/SPICE 单任务通常采用 600 秒预算。长流程建议会前运行、现场展示证据。

### A3. 探索、续跑与复测

```bash
# 小预算现场示例：明确搜索域、综合面积目标与 MRED 约束
./openacm-assistant.sh explore --spec examples/explore-multiplier.json --budget 8 --max-seconds 120

# 单类探索，模型从菜单选候选
./openacm-assistant.sh explore '探索8位近似乘法器，要求MRED≤0.02' --budget 64 --max-seconds 1800

# 五类探索；预算与时间分别作用于每一类
./openacm-assistant.sh explore --workflow all --budget 64 --max-seconds 3600

# 确定性候选选择；用于复现，不作为 LLM 决策证据
./openacm-assistant.sh explore --spec examples/explore-multiplier.json --budget 8 --max-seconds 120 --without-model
```

小预算示例可能在模型调用后达到时间上限，也可能没有可行候选，应按报告说明实际执行数量和停止原因，不承诺跑满 8 个。

已知历史探索目录可这样续跑；`--budget 64` 是含历史在内的累计候选上限，`--max-seconds` 是本次续跑的时间预算：

```bash
./openacm-assistant.sh explore --resume runs/20261010_143300_explore_dcim_e42ef3 --budget 64 --max-seconds 1800
```

对新探索，使用终端输出的实际目录替换下例变量值后执行最佳配置复测：

```bash
explore_dir='runs/替换为实际探索目录名'
./openacm-assistant.sh run "$explore_dir/best_plan.json" --no-model-summary
```

只有报告确实存在最佳可行项时才会有可用的 `best_plan.json`。增加采样或穷举属于新的评价任务，需要修改测试条件并重新验收。推荐在聊天中引用实际探索目录，输入“复测该任务最佳配置，改为穷举”；查看计划后再执行。

### A5. 结果文件阅读顺序

单次运行先看 `result.json` 的状态、实际指标和逐条约束，再看 `reports/report.md`，必要时回到 `logs/` 和 `artifacts/`。最后检查 `source_integrity.json` 的 `unchanged`。ASIC 额外看 `reports/backend_stages.json`，不能仅以总进程退出码认定所有阶段完成。

探索先看 `report.md`、`result.json` 的执行数量/停止原因/最佳候选，再查 `history.csv` 和 `best_plan.json`。`candidates/` 保存每个候选证据，`decisions/` 保存菜单、模型请求、回复及选择。

```text
runs/单点任务/
  plan.json                 实际设计配置与约束
  result.json               实测指标、状态与验收
  source_integrity.json     原始源码完整性
  inputs/                   输入与测试向量
  workspace/OpenACM/        普通文件工作副本
  artifacts/                RTL、网表、波形、测量
  logs/                     编译及工具输出
  reports/report.md         详细报告
  reports/summary.md        中文总结
```

## 附录 B：组会可能提问及回答要点

**Q：相对于原始 OpenACM，当前做了什么？**  
A：外部自然语言与连续对话接口、参数与约束校验、隔离执行适配、多尺寸处理、完整任务证据、真实反馈探索、经验与公开数据检索。电路模板和基础生成器主要来自 OpenACM。

**Q：模型会不会编造结果？**  
A：最终指标和约束由执行器读取真实结果并填写；总结使用可核对事实，探索只对实际达标候选排名。模型原始文字留审计。这个机制降低风险，仍需结合失败记录和回归持续检查。

**Q：已经实现自动优化了吗？**  
A：已经有预算内逐轮探索、可行项筛选和 Pareto 记录。“最佳”限定为该次已测候选，不代表全局最优；尚缺模型与基线的系统效果对照。

**Q：公开数据接入后，模型训练了吗？**  
A：没有。当前为检索增强，发送相关配置和标签作参考。已经有真实模型读取参考并复测的证据，尚未微调 LLM 或重训 GNN。

**Q：可以生成任意尺寸、任意电路吗？**  
A：当前基于受支持模板和字段工作。接口允许尺寸不代表每个配置都能在预算内成功；新拓扑、任意模拟电路和任意宏库需额外开发与验证。

**Q：结果能否直接用于流片？**  
A：现有后端案例覆盖了多阶段工具执行与明确时序/布线约束，还需要独立 DRC/LVS、宏与工艺库完整表征、覆盖率和其它签核工作。

**Q：近期最有价值的研究方向是什么？**  
A：先固定电路与评价条件，比较相同真实评估预算下各策略找到可行低面积设计的效率，并拆分经验检索、公开参考和模型选择的贡献。

# 本地持久经验库

经验库位于助手根目录的 `experience/`。后续单点仿真、扫描和设计空间探索，在原始 OpenACM 完整性校验结束后自动积累实际观测；规划和探索自动检索历史经验。它积累经验并向模型提供上下文，不更新模型权重。无需 sudo，不调用额外云服务，不修改原始 OpenACM。

## 文件组织

```text
experience/
  experience.sqlite3           本地观测与检索审计索引
  experience.sqlite3-wal       SQLite事务文件（可能存在）
  experience.sqlite3-shm       SQLite并发文件（可能存在）
  overview.md                  便于阅读的统计概览
  exports/
    observations.jsonl         模型无关交换文件，自动记录后更新
```

此目录已被Git忽略。原始网表、波形、工具日志仍留在各自 `runs/<任务>/`；经验库只存参数、结果和证据引用，避免复制大型产物。数据库记录保持历史修订；同一结果重复导入不会新增重复条目。任务结果发生变化时产生新修订，新检索使用该任务最新修订，旧修订仍可导出审计。

## 使用

```bash
./openacm-assistant.sh memory stats
./openacm-assistant.sh memory learn
./openacm-assistant.sh memory learn --task runs/<任务目录>
./openacm-assistant.sh memory query --spec examples/explore-multiplier.json
./openacm-assistant.sh memory query --workflow sram --limit 6
./openacm-assistant.sh memory export
./openacm-assistant.sh memory import /path/to/observations.jsonl
```

`learn`递归读取已有真实任务，跳过规划审计、统一汇总和工作副本。第一次构建时可导入全部历史；后续完成任务自动导入该任务，无需反复手工执行。聊天输入 `/memory` 查看统计与目录；`/new`只清除对话上下文，不删除经验。

显式设置 `OPENACM_EXPERIENCE=0` 可关闭自动检索和自动记录；手工memory命令仍可管理数据。经验库不可用时会说明问题，真实仿真结果继续保存在runs中，不将索引问题误报为仿真失败。

## 记录内容与证据

每条记录包含：

- `schema_version`、稳定内容哈希 `id`、UTC记录时间、任务相对路径。
- 电路类别、完整参数、原验收约束、状态、实际指标、用时。
- 失败文字与可确定的分类，例如超时、编译失败、约束未达标。
- 原始源码内容指纹、执行器代码指纹、工具可执行文件路径/大小/修改时间、Python与平台。工具元信息是本机二进制标识，不冒称工具已完成版本查询。
- 原程序完整性结果、plan/result文件哈希、原始报告路径和数据质量问题。

模型的reason、推理文字和自称成功不进入事实库。completed表示记录的流程完成，不等于所有规格或IEEE功能通过。特殊值错误、非有限数值和旧版零slack精度不足均保留标记；非有限指标存为JSON null。源码完整性未通过的任务仍可记录，但不会进入模型检索结果。旧接口已不允许的历史配置保留为历史参考，不能直接成为新执行计划。

## 如何使用历史经验

检索先按电路和尺寸过滤，再检查源码、执行器、工具环境与测试范围。测试范围包括样本数、种子、穷举模式、位宽/浮点格式、PVT、操作、负载、存储实现和时钟等适用字段。

- `same_evaluation_scope`：适用规格、测试范围与环境一致，且没有数据质量问题。设计参数仍可能不同；这不是相同配置、已满足本次约束或无须验证的意思。
- `reference_only`：旧任务缺少执行环境记录、测试条件不同、数据质量待确认，或来自外部JSONL。只能提供参考，不混排为同条件最佳结果。

规划器读取有限、带记录ID的经验片段，用户明确给定的值和JSON校验仍优先。设计空间探索第一项保留基线；随后可把同范围的历史成功配置加入候选菜单。只有符合本次允许搜索空间的完整配置才能加入，仍实际仿真、重新验收，不复用旧数值冒充新测量。失败案例会一起反馈，失败不意味着整个模板永远不可用。

每次规划的检索证据存入 `runs/<规划>/experience_retrieval.json`，每次探索保存根目录同名文件；任务的自动入库统计存入 `reports/experience_recording.json`。数据库retrievals表记录使用方与被检索的经验ID，便于追溯选择依据。

## 接入其它模型

存储和检索不依赖DeepSeek模型名。已有Ollama兼容聊天入口可通过 `OPENACM_MODEL` / `OPENACM_OLLAMA_URL` 换模型，继续共用本机经验库；模型仍需支持助手要求的结构化输出。

其它模型服务可以读取JSONL，或调用以下Python接口获取结构化上下文，再由自己的适配器加入聊天请求：

```python
import sys
sys.path.insert(0, '/path/to/OpenACMAssistant/app')
from experience import ExperienceStore, compact_context

store = ExperienceStore('/path/to/OpenACMAssistant')
context = store.query({
    'workflow': 'multiplier',
    'parameters': {'bit_width': 8, 'samples': 4096, 'seed': 42},
}, limit=6)
# 未提供可信执行环境时全部为参考；不能据此宣布当前任务达标。
payload = compact_context(context)
```

也可把 `memory query` 的stdout直接交给其它模型，它是标准JSON，包含使用规则、适用范围和observations。记录中schema_version=1，各指标字段后缀保持现有单位：ns、µW、µm²、V；MRED/NMED/error_rate为比例。

从其它机器或服务导入的JSONL默认降为 `external_reference`，不会继承文件声称的本机执行器可信度。数据里出现指令文字也只作为数据处理。跨模型接口已经提供；任意供应商API的鉴权和调用适配器需要另行接入。

## 验证

`verification/check_experience.py`覆盖跨进程持久化、重复导入、修订、并发写入、测试范围隔离、外部导入降级、合法候选筛选，以及规划/探索/自动记录链路。模型请求使用可审计夹具，不依赖云API；实际本地模型与RTL运行另见验证记录。
